# AedileBot data parity: scope and bot capabilities

Date: 2026-11-08

## Goal and guardrail

The goal is data parity, automated: the pipeline regenerates `Locations.csv`, `Weapons.json`, `Targets.json`, `Damage.json` and `Bunker_piece.json` so they match what the bot uses today, with no hand steps.

- The game data is the source of truth. Where the sheet disagrees with it, the generated value wins and the difference is reported as a sheet error, not reproduced. Example: the Nemesis row pairs the 68mm cannon with the grenade launcher's 3.5s reload; the generated value is 7.0s.
- Values the game data cannot supply (armour type for native-class structures, free-text notes) stay a hand-maintained overlay.
- Open-ended investigation into why the game behaves as it does (Watchtower armour, reverse engineering) is out of scope.
- Automation (runner, PR creation, build detection) comes after parity is proven.

## What the bot answers

The bot answers four kinds of question, all calculated from the data files. Each reads the columns below, so those are the columns the pipeline must reproduce.

| Question | Entry points | Reads |
| --- | --- | --- |
| Hits to kill | `/kill`, `/how`, free text "how many X to kill Y" | Weapon damage and damage type; target health and mitigation type; the damage-profile table. Multi-tier structures are computed per tier. Location names work as targets. |
| Hits to disable | `/disable`, free text "to disable" | Vehicle `Disable Level`, plus the kill inputs. Vehicles only. |
| Hits to dehusk | `/dehusk`, free text "to dehusk" | Same as kill, restricted to husk targets. |
| Bunker kill | `/bunker_kill`, free text with size, tier and modifiers | `Bunker_piece.json`, shelter bonuses, total size, tier, modifiers (ATG, RG, HG, MG, med, ammo, core), green and red dots, wet hours. |
| Custom kill | `/custom_kill` | N hits already landed with weapon 1, then hits of weapon 2 to finish. Same inputs as kill. |
| Statsheet | `/statsheet` | Weapons: damage, damage type. Structures: health, mitigation type, decay start hours (shown as "Repair Cost", a preserved bug). Vehicles, emplacements, tripods, aircraft parts: health, mitigation type, min and max penetration chance, armour health, reload, main weapon, main-gun and track disable chance. Multi-tier: health, bmat cost, repair cost. |

The statsheet is the only place that reads the vehicle reload, main weapon, penetration and disable-chance columns.

## Vehicle weapon mapping (settled)

Resolved with `scripts/resolve_vehicle_weapons.py`; the review is in `docs/vehicle-weapons-report.md`. 62 of 77 vehicles with sheet weapon text agree; every disagreement reviewed was a sheet error or a text-format difference, none a mapping error.

- Chain: vehicle blueprint (follow `SuperStruct`) -> seat -> `MountCodeName` / `MountComponent` -> `BPMountDynamicData` row (range, firing time, reload, magazine) and component ammo list -> `BPAmmoDynamicData` damage -> `Weapons.json` name.
- A seat is a named object (`GunnerSeat1_GEN_VARIABLE`); a child blueprint's properties override the parent's seat of the same name, and `bIsEnabled: false` removes it.
- Main weapon = firing seat (`MaxDistance > 0` or `MaxAmmo > 0`) with the highest ammo damage; ties go to the lowest seat number. Loader seats (Lordscar engineer) have neither and are excluded.
- Effective range = component `AimOffsetStartRange` if present (Stockade, Stygian Bolt), else `MaxDistance`. Max range = `MaxReachability`.
- Reload: store firing time, reload time and magazine (`MaxAmmo`) as separate fields; the bot builds the display text. Sheet text ("2x", "(75r)", "0s?") is not parsed.
- Secondary weapon = the next-best firing seat with a different mount (same ranking as the main weapon). Sheet text is filled for only 12 vehicles; generated has 39. Highwayman (`MediumTank2MultiW`) has two seats: the 14.5mm gun and a commander MG (`MGAmmo`, 125 rounds, 3.5s). The sheet's 7.92mm / 50 rounds is the Outlaw's text pasted onto it: sheet error. Silverhand Mk. IV sheet reload 7.5s vs export 4.5s: sheet error.
- Count: identical mounts on separate seats (Phalanx, Scorpion) are one weapon with a mount count; a magazine of 2 (Ares) is not a mount count.
- Lookups need case-insensitive matching (Dev Name vs file name, `HalftrackMultiWGunner`, `RpgAmmo`) and blueprint files without a `BP` prefix.
- Gaps the export cannot fill: Knave grenade launcher firing time (mount row `ArmoredCar2TwinGunnerW` has `FiringDuration`, `MaxDistance` and `MaxReachability` all 0, and no other table or the gunner component has a firing time; wiki says 0.75s; decision pending: hand overlay of 0.75, wiki-sourced; also compare the wiki's reload and magazine with the row's 2.0s and 2 rounds; range is computed, below). Fabricator has no weapon.
- Grenade and launcher range is computed, not read. The mount row `MaxDistance` (4000) is only a targeting limit and `MaxReachability` is 0 for grenade launchers. The max range comes from the grenade's `MaxTossSpeed` (`BPGrenadeDynamicData`, cm/s) with `DefaultGravityZ` -980 (`War/Config/DefaultEngine.ini` in the modding extract) and an empirical launch height: `range = v / g * sqrt(v^2 + 2 * g * h)`, `h` = 320 cm. The game's own launch-speed rule is in native code and not exported, so `h` is a fitted constant. It reproduces all four wiki ranges to the nearest metre: Mammon 91-b (900) 11.0m vs wiki 11, Green Ash (1100) 15.2 vs 15, PT-815 Smoke (1300) 20.2 vs 20 (predicted before reading the wiki page), Mounted Fissura gd.I (1650) 30.8 vs 31. The KLG901-2 Lunaire F (`GrenadeLauncherC`, 1650) predicts 30.8m, confirmed by the user in game knowledge; the `Rifle*` rows (1550, 27.5m) are rifle-mounted launchers; the Knave (`ArmoredCar2TwinGunnerW`, 1550) gets 27.5m from the model, confirmed by the user. Any `h` from 286 to 355 cm fits all four. Revalidate `h` when the game updates grenade physics or when more wiki ranges disagree. Firing duration, reload, magazine and the 90 degree arc come from the mount row and match the wiki.

## Mitigation type and blueprint lookup

`data/Targets.json` is the current hand sheet, not generated; we do not fix it. Its Dev Names are evidence for what the generator must resolve, and where they are wrong the generator uses the game's key.

- Source: the blueprint's `ArmourType` property (`EArmourType::Tier2Structure`), first hit following `SuperStruct`, child first. Checked by `scripts/check_armour_type.py BP_DIR`: vehicles 177/177, multi-tier 7/7, structures 211/260.
- A data-table row key is the blueprint's `CodeName` property, not its file name (`GarrisonStation1` is the `CodeName` of `TownWLargeG1`). Look up by file name (`BP<name>`, case-insensitive) first, then `CodeName`.
- Aircraft parts: health (`Health`), disable level (`DamagedThreshold`) and repair cost match `BPAircraftPartDynamicData` 40/40. Armour type is on the aircraft blueprint (`Tier1Aircraft`), found by stripping `Engine`/`Fuselage`/`Tail`/`Wing` from the part name.
- Sheet Dev Names that are not game keys: FuelContainer (`LiquidContainer`), SmallShippingContainer (`ShippingContainer`), FacilitySupplyStation (`MaintenanceTunnel`), DepotCrane (`StaticCrane`), Tier3BStructure (`TankStopSplineT3`), blank Navy Pier (`FieldPier`), GarrisonStation (`GarrisonStation1`), FirePit (`FirePitT1`, no `ArmourType`). Player and Colonial Player are characters with no structure row.
- No `ArmourType` anywhere in the chain (39 structures, e.g. Hospital, Keep, Seaport, Shipyard): native-class defaults, hand overlay.
- No blueprint in the game files for Garage, OilWell, WoodBridge: the export is complete (1019 `Blueprints/Structures` files in the paks and in the export), and a name-table scan of every package outside `Blueprints/`, Textures, Audio, Materials, Animation and FX for those names plus `DrawbridgeWood` found only meshes. They look like stale data rows: `Garage` equals `VehicleFactory` (whose display text is "Garage"), `WoodBridge` equals `DrawbridgeWood`, `OilWell` matches the old mine rows (ComponentMine, ScrapMine and SulfurMine have blueprints, OilWell does not; `SK_OilWell` is used by `BPFacilityMineOil`). Armour type for them stays the sheet value. 83 of 592 structure rows lack a blueprint, mostly `Destroyed*` and `*BuildSite`; the generator skips rows with no blueprint.
- Emplacements (24 sheet rows = 12 guns x unemplaced/emplaced): the 12 blueprints are in `Blueprints/Structures/Emplacements/` (`BPEmplaced<Code>.json`, excluding `*Rotator`, `*Mount`, `*Gunner`); health is in the blueprint (`MaxHealth`) and equals the `BPStructureDynamicData` row of the same `CodeName`. The product name appears only in the description text (Lariat, Hades Net, Zeal, Bolas, Starbreaker, Ruptura, Serra and so on), so the name-to-code join was assumed to be a small hand table (superseded: each gun blueprint has its own `DisplayName`, and `gen_emplacements.py` needs no table; the list below is only the sheet-name mapping, for aliases): EmplacedLightArtilleryW = Lariat, MultiC = Hades Net, InfantryW = EMG, ATW = EAT, HeavyArtilleryC = Thunderbolt, HeavyArtilleryW = Exalt, IndirectC = Polybolos, CannonLargeC = Ruptura, ATLargeW = Starbreaker, InfantryC = Serra, AAC = Zeal, AAW = Bolas (matched by health and description, not yet by weapon data). Sheet Zeal and Bolas show 2650; the export says 1250 (sheet error). The sheet's "Emplaced" rows are the gun placed inside a Trench Emplacement (wiki: quadruples health, doubles rotation speed). The source is the gun blueprint's `EmplacedIncomingDamageModifier` (0.25, so emplaced health = `MaxHealth` / modifier) and `EmplacedTrackingModifier` (2.0). All 10 guns that have the modifier reproduce the sheet (750 to 3000, 1000 to 4000, 1250 to 5000, 1500 to 6000, 1650 to 6600, 2650 to 10600). Zeal (`EmplacedAAC`) and Bolas (`EmplacedAAW`) have no damage modifier and tracking 1.0: no trench bonus, emplaced health = 1250. The sheet's 2650/2650 for them is a sheet error.
- Tripods (11 sheet rows, 13 `Deployed*` blueprints in `Structures/`, `BPDeployed<Code>.json`, excluding `*Ghost`): health (`MaxHealth`, 1200) and armour (`Tier1Tank`) come from the blueprint, as for structures; repair cost is the `BPStructureDynamicData` row (40, or 20 for the siren, wind sock, listening kit and tripod). The weapon is the blueprint's `MountCodeName`, joined to `BPMountDynamicData` (range, reload, magazine). Sheet names are weapon names, not blueprint names; join by mount stats: Foebreaker = `DeployedRPGTW` (2 rounds, 4s, 35m/40m), Mounted Bonesaw = `DeployedATRPGTW` (1 round, 3s), Typhon = `DeployedATRifleTC` (10 rounds, 3.5s), Lamentum = `DeployedMGTC` (reload 5s), Ratcatcher = `DeployedMGTW` (reload 4.5s), ISG = `DeployedISG`, Grenade Launcher Tripod = `DeployedGrenadeLauncherTC` (4 rounds, 3s; reach is 0 in the export, a known gap). Sheet errors, export wins: Typhon range 34.5m/40m vs export 39.5m/45m; Lamentum magazine 250 vs export 200, Ratcatcher 175 vs 150. Siren, Wind Sock, Listening Kit and Tripod have no weapon. `DeployedExplosiveTripod` and `DeployedSatchelChargeT` (health 1, Havoc Charge) are not tripod weapons: the devs reused the tripod mechanism for a two-part, C4-like system (the tripod is placed first, the charge attaches to it, and shooting it triggers it). They are not on the sheet, so the generator excludes them from Tripods.

## Weapons columns (`Weapons.json`)

107 rows, 98 with an ammo row in `BPAmmoDynamicData` (key = `Dev Name`).

- Damage type: the ammo's `DamageType` class (`BP<X>DamageType_C` in `Blueprints/DamageTypes/`) has a `Type` property (`EDamageType::Explosive`). It reproduces the sheet on 96 of 98. The 2 misses are Flame Ammo and Flame Backpack Ammo: export `Incendiary`, sheet `IncendiaryHighExplosive` (both are `DTDamageProfiles` rows, so this changes bot output; decided: export wins, the generator emits `Incendiary`).
- Shelter bonus: the game flags it per damage-type class, `bAffectedByShelterBonus: true`, not per sheet type name. Flagged classes: `BPHighExplosiveDamageType`, `...FalloffDamageType`, `...LeakDamageType`, `...RuinDamageType`, `...AircraftTorpedoDamageType`, `BPBombHighExplosiveDamageType` and `BPIncendiaryHighExplosiveDamageType`. Not flagged: `BPIncendiaryDamageType` (the flame ammo) and `BPHighExplosiveBreachingLeakDamageType` (one weapon, which the sheet labels `HighExplosive`). So the flame rows correctly have no shelter bonus and the sheet's `IncendiaryHighExplosive` for them was a sheet error. The bot (`damageCalculator.ts:195`) tests the type name, `HighExplosive` or `IncendiaryHighExplosive`: it wrongly gives flame the bonus today, skips `BombHighExplosive` (Raidbreaker, flagged) and gives the bonus to the one unflagged breaching-leak weapon. The generator should emit the flag per weapon (or the bot should read it) instead of the bot inferring from the type name. Bot change not made..
- Damage = ammo `Damage` x 1.25 for `*Kinetic` damage types and `AircraftAmmo` (the 1.25 is in no exported table, kept as a constant in `gen_weapons.py`) x the `DamageMultiplier` of the firing weapon's own row: `Infantry Weapon Dev Name` -> `BPWeaponDynamicData`, `Mount Dev Name` -> `BPMountDynamicData`, neither -> 1. This reproduces 91 of 98.
- `data_manual/weapon_multipliers.json` (43 entries, seeded by `gen_weapons.py --seed`) is not a real mapping: the seed picks any row whose multiplier numerically ties (Stygian Bolt -> `MGTC`, Starbreaker -> `MGTC`). The generator should use the weapon's own mount or weapon row instead and drop the overlay.
- The 7 rows outside that rule are all velocity-modifier weapons (HV = high velocity, LV = low velocity; the percentage is the mount's `DamageMultiplier`). All 7 reproduce from the right mount row; the sheet's own fields are wrong or missing for them. Aircraft weapons are listed in the aircraft blueprint (`Vehicles/Aircraft/<Name>/BP<Name>.json`) as `WeaponCodeName` entries (e.g. `AircraftFighterW_Cannon`), not as `MountCodeName` seats, so the vehicle weapon resolver does not cover them and needs a second path. Resolved: Luminary Harbinger 14.5mm +50% = `AircraftFighterW_Cannon` (1.5; the sheet names `_HMG`, 1.0); Daimon aK-5 Harpy 20mm and 14.5mm +25% = `AircraftFighter2C_Cannon` (1.25); Tulka White Raven 20mm +25% = `AircraftWaterW_HMG` (1.25; the sheet names `AircraftFighterW_Cannon`, 1.5; White Raven is the `AircraftWaterW` blueprint); Ship 12.7mm and 20mm +20% = the `LargeShip*MachineGunner` mounts (1.2); Austringer torpedo -30% = `AircraftTorpedoWDriver` (0.7) firing `AircraftTorpedoAmmo` (the Tenta Torpedo, 1500), giving 1050; the wiki shows 1038 because it lists the in-game damage 1483 (datamined 1500, "not accounting for a longstanding bug with projectile damage values"; 1483 x 0.7 = 1038). We keep the datamined value, as the sheet does; the projectile bug is out of scope. The sheet row pairs it with `TorpedoAmmo` (Moray, 3550) for 2485: sheet error, export wins.
- 9 rows have no ammo row (garrison and AI shells). 7 of them are derived by `gen_weapons_layout.py` from the AI structure blueprints, which carry `WeaponDamage` and `DamageType` themselves: ATGT1-3 (300/600/600), Large Ship AI Shell (650), AI Anti-Air (2400), Coastal Gun (900), and ATPillbox (65 x 1.25 kinetic = 81.25, sheet 81). Rifle Garrison (sheet 50) is the non-infantry block, emitted as `bprifleait*:WeaponDamageAlternate` (`source: ai-nonInfantry`); the generator emits both blocks for every AI weapon. Howitzer Garrison (sheet 500) is `BPArtilleryAIT1-3` (named "Artillery Garrison"): `DamageParams.BaseAmount` 500, `BPHighExplosiveDamageType`, radius 11.25m, inner radius 4m, falloff 2, identical on all three tiers (only the accuracy radius and cooldown differ); emitted as `bpartilleryait*:DamageParams`. Caveat: blocks with no `DamageType` (Rifle and MG garrisons) get no kinetic factor and a null damage type, although the wiki calls them Light and Heavy Kinetic. Rifle AI blueprints (`BPRifleAIT1-3`, 40) and the rifle pillbox (45) carry a second `DamageAttributesAlternate.WeaponDamage` of 50, which is the sheet's 50. The wiki (Rifle Garrison page, checked 2026-11-08) explains both: the garrison deals 45 Light Kinetic against infantry and 50 Heavy Kinetic against everything else (vehicles, structures, emplacements), so `DamageAttributesAlternate` is the damage against non-infantry and the sheet correctly lists the one the bot needs. The wiki's 45 matches the rifle pillbox (45) but not `BPRifleAIT1-3` (40); not investigated. Damage falls off past 27m and stops at 43m (retaliation range). Likely the same split applies to the MG AI blueprints (55 / 50).

## Locations (`Locations.csv`)

`scripts/gen_locations.py ACTORS_JSON STATIC_DIR` writes `data/locations.gen.csv` (hex, name, type). Actors come from the extractor spike (`D:/work/extractor_spike/all.json`: TownBase1-3 = Post Office / School / Town Center, RelicBase1-3 = Small / Medium / Large Relic; identical coordinates collapse). Names are the nearest War API `mapTextItems` marker from `/worldconquest/maps/<Hex>/static` (fetched to `D:/work/warapi/static`), matched one-to-one, accents folded to ASCII. The bot reads only name -> type (`loader.ts`; the hex column is unused, and "TH" labels map to the same targets), so types are emitted canonical and the hex column is the export id. Result: 424 locations in 52 hexes vs the sheet's 428 in 53; 35 of 49 comparable hexes identical. Marban Hollow is missing from the spike's actors file (re-run the extractor). Differences in the other 14 hexes are sheet typos fixed by the generator (Headsman's Villa, Oleander Homestead, Manacle, Gorgon Grove, Erastos, Atropos' Fate, Shattered Advance), name differences (Harpy / Harpy Relic, The Blemish), and content differences, reviewed 2026-11-08 against each actor's nearest markers (export wins by the project rule; exact markers sit within 0.005 of the actor): Tine is a School actor (0.0009), there is no Town Center actor in Speaking Woods; The Bailie is a School (exact, 0.0) and Southblade the Small Relic; Slipgate Outpost is a Medium Relic actor (0.0016) while Sickleshire is the Large; Second Man is a Small Relic actor; Foxcatcher (Weathered Expanse), Callum's Descent (Morgen's Crossing) and Base Sagitta (Stema Landing) are clear actors the sheet lacks; Breaker Town and The Pale House are both Post Offices (Cavilltown has no actor or marker nearby, probably renamed); The Fingers has 7 actors and the sheet's Captain's Dread and The Tusk (and The Evil Eye in Endless Shore) have no actor. Two matches are weak and unresolved: the Stema Landing Medium Relic named Verge Wing (0.0502, no closer marker left; the sheet calls Verge Wing a Small Relic) and the Olavi's Wake Post Office named Iltaku (0.0302).
